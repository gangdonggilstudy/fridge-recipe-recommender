## 추천의 기본 재료

### 선호 벡터 (preference vector)
사용자의 취향을 **숫자 목록**으로 표현한 것. 스타일(메인반찬·찌개·국/탕·밥/죽/떡·면/만두·양식), 맛(매운맛·담백함...), 조리시간, 리뷰 키워드 차원으로 구성됩니다. 예: `{찌개: 1.2, 매운맛: 0.8, short: 0.5, ...}`. 값이 클수록 그 특성을 좋아한다는 뜻. → `preference.py`의 `FEATURE_KEYS`

### 레시피 벡터 (recipe vector)
레시피를 선호 벡터와 **같은 칸(차원)** 으로 0/1 표시한 것(one-hot). 찌개 매운 요리면 `{찌개: 1, 매운맛: 1, ...}`. 사용자 벡터와 이 벡터의 **코사인 유사도**가 선호도 점수가 됩니다. → `scorer.build_recipe_vector()`

### 코사인 유사도 (cosine similarity)
두 벡터가 얼마나 같은 방향을 가리키는지 0~1로 잰 값. 1이면 취향이 완벽히 일치, 0이면 무관. "내 취향 벡터와 이 레시피 벡터가 비슷한가?"를 재는 데 씁니다.

## 점수의 5요소

추천 점수는 아래 5개를 합쳐 만듭니다. → `scorer.py`, `ingredient_matcher.py`

### 재료 일치도 (ingredient score)
레시피가 요구하는 재료를 사용자가 얼마나 갖고 있는지. 가중치 0.35로 **가장 무겁습니다**. 정확히 없어도 **같은 카테고리**(예: 돼지고기↔소고기=육류) 재료가 있으면 부분 점수.

### 소모 우선순위 (consumption score)
**곧 상하는 재료**를 쓰는 요리일수록 높음. 오늘 유통기한이면 1.0, 7일 남았으면 0.0으로 선형 감소. "냉장고 비우기"를 돕는 점수.

### 선호도 (preference score)
위의 선호 벡터 ↔ 레시피 벡터 코사인 유사도. "내 취향인가?"

### 상황 적합도 (context score)
지금 **시간·날씨·계절**에 어울리는지. `0.55×시간 + 0.29×날씨 + 0.16×월`로 합산.

### 다양성 보너스 (diversity bonus)
추천 목록이 한 종류로 쏠리지 않게 주는 가산점. → 아래 "다양성 2-pass" 참고

## 두 가지 추천 방식 (가장 중요!)

이 앱은 점수 5요소를 **두 가지 방법**으로 합칩니다.

### 룰 레짐 (rule regime)
데이터가 없을 때 쓰는 **고정 규칙**. 5요소에 정해진 가중치를 곱해 더합니다.
`0.35×재료 + 0.25×소모 + 0.20×선호 + 0.15×상황 + 0.05×다양성`
모든 사용자에게 동일. → `Scorer._rule_total()`

### 블렌더 레짐 (blender regime)
사용자 기록이 쌓이면(50건+) 학습된 **개인 AI**가 5요소를 합칩니다. 어떤 요소를 더 중시할지 그 사람 데이터로 배운 가중치를 씁니다. → `Scorer._apply_blend()`

### 콜드스타트 (cold start)
신규 사용자라 데이터가 거의 없는 상태. 학습할 게 없으니 ①온보딩 취향 → ②인구통계(성별·나이대) **그룹 평균** → ③룰 레짐 순으로 메꿉니다. "추천의 시작점 문제."

## 머신러닝 용어

### 로지스틱 회귀 (Logistic Regression, LR)
이 앱이 쓰는 ML 모델. "사용자가 이 추천을 **선택할 확률**"을 0~1로 예측합니다. 사용자마다 따로 학습한 작은 모델을 가집니다. → `ml_trainer.py`

### 피처 (feature)
ML 모델의 입력 숫자. 여기선 5개: 재료 일치도·소모·선호·상황 점수 + **시기 적합**. → `ml_model.FEATURES`

### temporal_fit (시기 적합)
"지금이 이 레시피에 얼마나 제철인가"를 한 숫자(서수)로 담습니다 — **1.0** 달까지 정확 / **0.5** 달은 아니어도 계절은 맞음 / **0.0** 계절도 불일치. 옛날엔 '월 적합'·'계절 적합' 두 0/1 피처로 나눴는데, 달이 맞으면 계절은 **자동으로** 맞는 포함 관계라 중복(대부분 레시피에선 두 값이 똑같음)이어서 한 서수로 합쳤습니다. → `context.temporal_fit_score` ([06_ml_explained.md](06_ml_explained.md))

### 활성화 임계값 (activation threshold) = 50
사용자 기록이 **50건** 이상 쌓여야 개인 AI 학습이 시작됩니다. 그전까지는 룰 레짐. → `ml_model.ACTIVATION_THRESHOLD`

### 재학습 간격 (retrain interval) = 25
첫 학습 후, 기록이 **25건** 더 늘 때마다 모델을 다시 학습합니다. → `ml_model.RETRAIN_INTERVAL`

### 최신성 가중 / 시간 감쇠 (recency decay) = 0.95
오래된 데이터일수록 영향을 줄이는 장치. 매 갱신마다 0.95를 곱해 14번이면 절반으로 줆 → 취향 변화 추종. 선호 벡터와 ML 학습이 **같은 0.95**를 공유합니다.

### 설명가능성 / 충실성 불변식 (fidelity invariant)
AI가 "왜 이 추천?"을 숫자로 정확히 분해해 보여주는 것. LR의 내부 계산(`decision_function`)을 피처별 기여도 `wᵢ·xᵢ`로 쪼개되, **합치면 원래 값과 정확히 같도록**(불변식) 보장합니다. → `Explainer`, `ml_trainer.linear_contributions()`

## 추천 정렬 & 피드백

### 다양성 2-pass (two-pass diversity)
정렬을 **두 번** 하는 기법. ①먼저 순수 점수로 정렬해 상위 3개 스타일을 확정 → ②그 외 스타일에 +0.2 보너스 → ③다시 정렬. 찌개만 5개 뜨는 걸 막으면서 상위권 우위는 유지. → `Recommender._apply_diversity()`

### 비대칭 피드백 (asymmetric feedback)
선택은 +1.0, 안 고름은 −0.5로 **다르게** 반영. "안 골랐다"가 꼭 "싫다"는 아니므로 약하게 처리. → `preference.update()`

### 거울 트랜잭션 (mirror transaction)
'별로에요'를 누르면 직전 선택을 **정확히 되돌립니다**: impression·history·선호벡터 3곳을 일관되게 원복(−1.5). → `Recommender.record_dislike()`

### impression (노출 기록)
추천 카드가 화면에 **보여진** 기록. 이걸 클릭(선택)과 비교해 **CTR(클릭률)** 을 계산합니다. 또한 보여줬는데 **안 고른** 노출은 ML 의 **약한 미선택**(약한 '아니오') 학습 신호로도 쓰입니다([06](06_ml_explained.md#선택만-하면-ai가-영영-못-배운다--약한-미선택-신호)). → `recommendation_impression.py`

### 하드 필터 (hard filter)
점수와 무관하게 **무조건 제외**. 알레르기·기피 재료가 든 레시피는 점수 계산 전에 빼버립니다(타협 불가). → `Recommender._apply_restrictions()`

## 기타 자주 보이는 것

### 레짐 (regime)
"방식·체제"라는 뜻. 여기선 룰 레짐 / 블렌더 레짐 = 점수 합치는 두 모드.

### fallback (폴백)
주된 방법이 안 되면 쓰는 **대체 수단**. LLM 키 없으면 템플릿, 날씨 API 없으면 "맑음" 고정 등. 이 앱은 모든 외부 의존성에 fallback이 있어 키 없이도 동작합니다.

### 멱등 (idempotent)
같은 연산을 여러 번 해도 결과가 같음. 다양성 보너스를 재계산해도 누적되지 않게 `base`를 따로 보존하는 설계가 그 예.

### XAI (eXplainable AI, 설명가능한 AI)
AI 결정의 근거를 사람이 이해하게 보여주는 것. 이 앱의 "왜 이 추천?" 점수 분해가 XAI입니다.
